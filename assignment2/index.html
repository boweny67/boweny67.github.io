Abstract · 摘要

这份文档要解决什么Business & System Requirements

本作业承接作业 1 的六层架构，落到一个具体整机实例：面向脑卒中后上肢运动功能障碍患者的混合辅助训练系统。生物通道保留患者残存的神经控制与本体感觉，人工通道由肌电采集、边缘决策、外骨骼/功能电刺激执行与触觉反馈构成。

BRS 从使命、业务约束、运营概念（ConOps）、运行概念（OpsCon）出发，把患者的康复诉求、治疗师的临床约束、监管方的合规要求整理成业务层面需要明确的需求；StRS 再把这些需求拆成可设计、可测试、可追溯的条目，覆盖功能、性能、接口、安全与设计约束。

两层文档对应两种验收口径：BRS 判断系统值不值得做，StRS 判断实现能不能测过。

Part Ⅰ · BRS

业务需求规范Business Requirement Specification

只回答「业务上要什么」，不回答「工程上怎么实现」。

1.1

业务使命与顶层任务

先说明系统存在的理由，再展开约束与指标。

系统的任务是：在维持患者生命稳态的前提下跑通感知—决策—行动回路；用机器单元代偿偏瘫侧缺失的运动输出，辅助患者完成抓握、伸展与日常取物。辅助功能均可启停、可降级，患者保留最高否决权。

基础业务

守住生命底线

训练全过程保障心率、血压、呼吸、体温等基础体征稳定。这一层不追求辅助效果，只保证不发生安全问题，是其余辅助功能的前置条件。

原生业务

延续残存感知—行动闭环

患者残存的神经通路仍感知环境、产生动作意图；系统要保护并延续这条通路本身，而不是绕开它直接控制肢体。

增强业务

代偿上肢功能缺失

补足偏瘫侧抓握、伸展的运动缺口，配合电刺激与触觉反馈帮助恢复自主活动能力。辅助是叠加项，不是替代项。

1.2

业务约束

这几条是硬边界，后面所有需求都不得违反。

BC-1
训练安全优先级最高。任何助力、刺激或触觉反馈，都不得威胁患者的生命安全与基础生理稳态。
BC-2
控制权可切换，人拥有最高否决权。患者或治疗师可以在任意时刻收回控制权，机器不得拒绝这一请求。
BC-3
满足医用生物相容性与电磁兼容安全规范。接触人体的材料、向人体输出的电流与能量，都须落在医用标准允许范围内。
BC-4
不破坏人体原有神经自主调节机制。系统失效或关停时，患者应能独立维持基本生命活动与休息体位。
1.3

业务性能指标

业务层面的「够不够用」用定性口径描述；定量指标留给 StRS。

BP-1
生命指标稳定可控。系统运行时，患者基础生命指标应稳定维持在医学正常区间内，不因辅助功能启停而显著波动。
BP-2
闭环延迟处于人体可接受范围。人机混合的感知—行动闭环，其延迟应不至于让患者产生明显的动作滞后或脱节感。
BP-3
辅助功能可启停、可降级。支持一键退回纯自主模式，且降级过程不影响患者的即时安全。

Part Ⅱ · ConOps

运营概念Concept of Operations · 业务层面怎么用

ConOps 描述「在什么业务场景下、由谁、为了什么目的使用这个系统」，不是系统的运行时序。

A

康复代偿场景（主例）

使用者 = 脑卒中后单侧上肢偏瘫患者

患者因神经损伤出现上肢运动通路缺失，机器单元承担代偿职责：采集残存肌电与关节信号，驱动外骨骼与功能电刺激，辅助其完成抓握、伸展等训练动作，逐步恢复自主生活能力。

运营模式为三方协同：治疗师/医师设定安全边界与辅助参数，患者在诊室、社区站或居家环境日常使用，运维技师负责校准与故障处理；辅助等级随康复进程阶段性调整，而非一次设定终身不变。

目标：恢复上肢自主活动能力主导方：临床治疗师调整频率：按康复阶段
B

对照 · 能力增强场景

使用者 = 健康人员，处于特殊作业环境

作为对照边界：健康人员在高危、狭窄、弱光或高负载环境中作业（如消防救援、精密检修、重物搬运）时，同类机器单元可承担扩展职责，拓宽感知通道、放大体力上限。此场景下系统不介入医疗判断。

该场景与康复代偿共用底层硬件架构，但业务目标、主导方与安全责任归属不同，后续需求不能把医疗场景的安全约束套到工业场景上，反之亦然。

目标：扩展作业能力主导方：使用者本人监督方：现场安全员

两个场景共用同一套架构，但业务目标、主导方与安全责任不同；本作业后续条目以康复代偿场景为主例展开。

ConOps 只写某类场景的运营构想，不写单次使用的时间线；单次时序归 OpsCon。

Part Ⅲ

运行概念 · Operational Concept

一次完整的训练回合里，信号从哪来、到哪去、谁在兜底。

多源感知并行采集

训练环境信号同时进入两路：患者原生感官，以及机器传感阵列（接触力、距离、姿态、声响）。两路互不替代，形成冗余的感知输入。

信号汇入混合决策单元

表面肌电、关节角度与机器传感信号在本地单元内完成同步、降噪与特征提取，为意图识别提供统一的时间基准。

双路指令输出

决策单元输出两路指令：一路经患者自身神经通路驱动残存肌肉；一路送往外骨骼、功能电刺激等机器执行单元。

执行反作用于环境

动作改变环境状态，新的感知信号回到第 1 步，闭环形成。

安全监控持续校验

安全监护子系统全程旁路运行，持续比对实时信号与预设阈值。一旦越界，按「提示 → 限制助力 → 强制停机」分级降权，最终交还患者完全控制权。

全程留痕

运行日志持续记录信号质量、辅助强度、越界事件与人工干预。日志供治疗师复盘康复进程，也供工程师定位算法缺陷。

旁路安全指监护不串在主链路里等待执行，而是并行监视：监护失效不拖垮主链路，主链路失效时它仍能切断输出。

4.1

相关方业务需求

只写「他们要什么」，不写「用什么技术满足」。每条都可以回溯到上面表格里的某一方。

使用者（患者）

最终用户 · 01
  1. 系统须安全无痛，长时间佩戴不引起明显不适
  2. 辅助功能随动作意图自然响应，无需刻意学习复杂操作
  3. 可随时关闭辅助，退回纯自主状态
  4. 不干扰正常呼吸、心跳、睡眠等自主生命活动

治疗师 / 康复医师

医疗评估方 · 03
  1. 可采集并导出体征与神经信号日志
  2. 辅助参数可由医师配置，且有明确安全锁
  3. 能区分「设备失效」与「患者状态变化」两类异常

研发工程师

系统实现方 · 02
  1. 系统模块化，便于单独替换传感或执行组件
  2. 接口标准化，软硬件可分别迭代
  3. 具备可复现的测试环境，仿真与实测结果可比对

监管与伦理方

合规审查方 · 04 / 05
  1. 运行记录可追溯，可还原每次辅助介入的上下文
  2. 具备故障安全机制，单点失效不导致人身伤害
  3. 材料与电流输出符合医用标准
  4. 不得无限制改造神经，不得改变人的基础自主意识

Part Ⅴ · StRS

系统需求规范System Requirement Specification

把业务语言翻译成工程语言。每条都应能被设计、被测试、被追溯。下面按类别筛选条目查看。

5.1

功能需求 FR

说明系统必须做什么。验收时逐条对应到具体代码或部件。

FR-1
采集患者表面肌电（EMG）与关节角度，以及心率、皮温等基础生命体征。
FR-2
采集训练环境的多模态传感信号，至少覆盖接触力、距离、姿态与声响四类。
FR-3
融合生物信号与机器传感信号，识别患者的上肢运动意图与发力水平。
FR-4
驱动上肢外骨骼、功能电刺激、触觉反馈等执行单元完成对应的助动动作。
FR-5
支持被动助动、主动辅助、纯自主三种控制模式切换。
FR-6
实时监测信号质量与生理指标，越界时触发保护动作并降级。
FR-7
存储运行日志，并支持日志导出与可视化回放。
FR-8
提供参数配置入口，供治疗师与工程师调整辅助阈值与安全边界。
5.2

性能需求 PR

每条都附带数值与验证口径；可量化是性能需求和普通功能需求的主要区别。

PR-1
意图识别端到端延迟 ≤ 200 ms。从信号进入决策单元到输出执行指令的时间，不含机械机构动作时间。
PR-2
体征采集精度满足临床监测要求。以同款医用监护仪为基准做对比标定，误差须落在其允许区间内。
PR-3
安全保护响应 ≤ 50 ms。从越界事件被检测到切断辅助输出的时间，须显著短于人体受到伤害的最短时间尺度。
PR-4
执行机构定位与出力误差在指标内。关节角度与输出力矩的稳态误差，按设计指标逐项验收。
PR-5
连续工作 8 小时无单点失效。考核项包含电量、温升、信号漂移与机械磨损，任一项超标即视为不通过。
PR-6
采集信噪比满足算法最低要求。以意图识别算法能稳定工作的最小信噪比为验收下限。
5.3

接口需求 IR

接口是系统与外部连接的位置，也是故障和安全风险最集中的位置。

IR-1
生物采集接口。干／湿电极接入，肌电与体征共用采集前端，接触面须为医用级设计。
IR-2
机器执行接口。外骨骼动力单元、功能电刺激器、触觉反馈模块采用统一的通信协议与供电规范。
IR-3
人机交互接口。提供触控终端，并保留独立的物理急停按钮，后者不依赖软件栈。
IR-4
数据接口。日志以通用格式导出，可在治疗师端软件中直接读取分析，不依赖专用上位机。
IR-5
供电接口。可充电电池供电，电源与人体之间须做电气隔离，防漏电与反向电流。
5.4

安全需求 SR

安全需求按失效即默认安全设计：坏了就停，而不是坏了还在跑。

SR-1
随时可切断。患者可通过原生动作或物理急停，在任意时刻切断辅助输出，此路径优先级高于一切。
SR-2
双重故障安全。软硬件各设一层保护，任一模块失效时系统默认回到无辅助状态。
SR-3
电气隔离。防止漏电与电刺激损伤神经组织，接触部位须限制输出电流上限。
SR-4
分级告警。信号异常或生命体征超标时，按「提示 → 限制助力 → 强制停机」三级递进响应。
SR-5
数据安全。存储的神经信号与健康数据须加密，访问须授权并留痕，满足隐私保护要求。
5.5

设计约束 DR

这些不属于功能需求，而是先限定方案空间的条件，通常来自标准、法规或既有架构。

DR-1
所有接触人体的材料须满足医用生物相容性要求。
DR-2
设备须电磁兼容，不干扰心脏起搏器等其他植入式医疗设备。
DR-3
整机须控制重量与体积，降低长期佩戴的负荷与体感负担。
DR-4
系统架构须与六层分解一致：任务 → 体系 → 整机 → 系统 → 子系统 → 模块。
DR-5
算法与硬件模块须可独立测试验证，避免出现只能整机联调的黑盒。
