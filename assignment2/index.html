Abstract · 摘要

这份文档要解决什么Business & System Requirements

同一件事，用两种语言各说一遍：业务侧说"为什么值得做"，系统侧说"做成什么样才验收得过"。

本作业以机器增强的人机混合神经系统为对象。BRS 从使命、业务约束、运营概念（ConOps）、运行概念（OpsCon）出发， 把使用者的生理诉求、医师的临床约束、监管方的合规要求，收敛成一组业务层面就该说清楚的需求； StRS 再把这些需求向下分解为可设计、可测试、可追溯的条目，覆盖功能、性能、接口、安全与设计约束。

两层文档的关系不是"摘要与细节"，而是两种不同的验收口径：BRS 的验收标准是"这个系统值不值得被做出来"， StRS 的验收标准是"这一版实现能不能被测试通过"。

人体的原生神经活动不能为增强功能让路——所有机器增强都是叠加在原有生命活动之上的，而不是替换它。
Part Ⅰ · BRS

业务需求规范Business Requirement Specification

只回答"业务上要什么"，不回答"工程上怎么实现"。

1.1业务使命与顶层任务

系统为什么存在——三句话讲清楚，下面再展开。

本系统的核心使命，是在维持人体生命稳态的前提下，闭环完成"感知—决策—行动"的神经活动， 并由外部机器单元扩展人的感知边界、响应速度与运动能力。它不是"给人体外加一个设备"， 而是让人体生物神经与人工系统在同一闭环里并行工作。

基础业务

守住生命底线

保障呼吸、循环、体温等生命体征稳定。这一层不追求增强，只追求"不出事"——它是所有增强功能的前置条件。

原生业务

完成感知—行动闭环

人体感知环境信号，经神经中枢处理，由躯体产生行动响应。这条通路本身就是系统要保护与延续的主体。

增强业务

突破生理边界

拓展可感知的频段（红外、超声），放大运动出力，代偿神经损伤造成的功能缺失。增强是附加项，不是替代项。

1.2业务约束

这几条是硬边界，后面所有需求都不得违反。

约束的作用是提前砍掉不可行的方案分支。以下四条一旦违反，方案在设计阶段就应被否决，而不必等到测试阶段才发现。

BC-1
人体安全优先级最高。任何机器增强动作，都不得威胁使用者的生命安全与基础生理稳态。
BC-2
控制权可切换，人拥有最高否决权。使用者可以在任意时刻收回控制权，机器不得拒绝这一请求。
BC-3
满足医用生物相容性与电磁兼容安全规范。接触人体的材料、向人体输出的电流与能量，都须落在医用标准允许范围内。
BC-4
不破坏人体原有神经自主调节机制。系统失效或关停时，人体应能独立维持基本生命活动。

1.3业务性能指标

业务层面的"够不够用"，用定性口径描述；定量指标留给 StRS。

BP-1
生命指标稳定可控。系统运行时，人体基础生命指标应稳定维持在医学正常区间内，不因增强功能启停而显著波动。
BP-2
闭环延迟处于人体可接受范围。人机混合的感知—行动闭环，其延迟应不至于让使用者产生明显的动作滞后感。
BP-3
增强功能可启停、可降级。支持一键退回纯人体原生模式，且降级过程不影响使用者的即时安全。
Part Ⅱ · ConOps

运营概念Concept of Operations · 业务层面怎么用

ConOps 描述"在什么业务场景下、由谁、为了什么目的使用这个系统"，不是系统的运行时序。
A

康复代偿场景

使用者 = 神经功能受损人群

使用者因神经损伤，出现感知通路或运动通路的缺失。机器单元承担代偿职责：接管缺失的感知输入，或驱动缺失的运动输出，辅助其恢复自主生活能力。

运营模式为三方协同：医师设定安全边界与增强参数，使用者日常自主使用，运维技师负责校准与故障处理。增强策略随康复进程阶段性调整，而非一次设定终身不变。

目标：恢复自主生活能力主导方：临床医师调整频率：按康复阶段
B

能力增强场景

使用者 = 健康人员，处于特殊作业环境

使用者在高危、狭窄、弱光或高负载环境中作业（如消防救援、精密检修、重物搬运），机器单元承担扩展职责：拓宽可感知的信息通道，放大可输出的体力上限。

运营模式为使用者主导 + 安全员监督：使用者自主管控增强模块的开关与强度，安全员负责监督安全边界是否被突破。此场景下系统不介入医疗判断。

目标：扩展作业能力主导方：使用者本人监督方：现场安全员

两个场景共用同一套硬件架构，但业务目标、主导方与安全责任归属完全不同——这一点必须在 BRS 里说清， 否则后续会把医疗场景的安全约束，错误地施加到工业场景上（或相反）。

ConOps 只描述"此类场景的运营构想"，不描述某一次具体使用的时间线。后者属于 OpsCon。
Part Ⅲ · OpsCon

运行概念Operational Concept · 系统跑起来是什么样

一次完整的运行回合里，信号从哪来、到哪去、谁在兜底。

多源感知并行采集

外部环境信号（光、声、压力、化学）同时进入两路：人体原生感官，以及机器传感阵列。两路互不替代，形成冗余的感知输入。

信号汇入混合决策单元

生物神经信号（脑电、肌电）与机器传感信号在同一单元内完成同步、降噪与特征提取，为意图识别提供统一的时间基准。

双路指令输出

决策单元输出两路指令：一路经人体自身神经通路驱动生物执行（肌肉、关节）；一路送往外骨骼、辅助刺激器等机器执行单元。

执行反作用于环境

动作改变了环境状态，产生新的感知信号回到第 1 步。闭环由此成立——这正是"感知—决策—行动"在运行时层面的具体形态。

安全监控持续校验

安全监控子系统全程旁路运行，持续比对实时信号与预设阈值。一旦越界，按"提示 → 限制增强 → 强制停机"分级降权，最终交还人体完全控制权。

全程留痕

运行日志持续记录信号质量、增强强度、越界事件与人工干预。日志供医师复盘康复进程，也供工程师定位算法缺陷。

运行概念的关键在于"旁路安全"：安全监控不在主链路上串联等待，而是并行监视，因此它失效不会拖垮主链路，主链路失效它也仍能切断输出。

4.1相关方业务需求

只写"他们要什么"，不写"用什么技术满足"。每条都可以回溯到上面表格里的某一方。

使用者

最终用户 · 01
  1. 系统须安全无痛，长时间佩戴不引起明显不适
  2. 增强功能应随动作意图自然响应，无需刻意学习复杂操作
  3. 可随时关闭增强，退回纯自主状态
  4. 不干扰正常呼吸、心跳、睡眠等自主生命活动

临床／康复医师

医疗评估方 · 03
  1. 可采集并导出生命体征与神经信号日志
  2. 增强参数可由医师配置，且有明确的安全锁
  3. 能区分"设备失效"与"使用者状态变化"两类异常

研发工程师

系统实现方 · 02
  1. 系统模块化，便于单独替换传感或执行组件
  2. 接口标准化，软硬件可分别迭代
  3. 具备可复现的测试环境，仿真与实测结果可比对

监管与伦理方

合规审查方 · 04 / 05
  1. 运行记录可追溯，可还原每次增强介入的上下文
  2. 具备故障安全机制，单点失效不导致人身伤害
  3. 材料与电流输出符合医用标准
  4. 不得无限制改造神经，不得改变人的基础自主意识
Part Ⅴ · StRS

系统需求规范System Requirement Specification

把业务语言翻译成工程语言。每条都应能被设计、被测试、被追溯。

5.1功能需求 FR

系统必须"做什么"。检验方式：逐条问"这一版实现里，哪段代码／哪个部件对应它"。

FR-1
系统应能采集人体原生神经信号（脑电 EEG、肌电 EMG）与基础生命体征（心率、血氧、体温）。
FR-2
系统应能采集外部环境的多模态传感信号，至少覆盖视觉、听觉、压力与距离四类。
FR-3
混合决策单元应能融合生物信号与机器传感信号，识别使用者的运动意图。
FR-4
系统应能驱动机器执行单元（外骨骼、辅助感知模块）完成对应的增强动作。
FR-5
系统应支持三种控制模式切换：自动增强模式、辅助模式、纯人体原生模式。
FR-6
安全监控子系统应实时监测信号质量与生理指标，越界时触发保护动作并降级。
FR-7
系统应存储运行日志，并支持日志导出与可视化回放。
FR-8
系统应提供参数配置入口，供医师与工程师调整增强阈值与安全边界。

5.2性能需求 PR

每条都附带数值与验证口径——"可量化"是性能需求和普通功能需求的唯一区别。

PR-1
意图识别延迟 ≤ 200 ms。从信号进入决策单元到输出执行指令的端到端时间，不含机械机构动作时间。
PR-2
生命体征采集精度满足临床监测要求。以同款医用监护仪为基准做对比标定，误差须落在其允许区间内。
PR-3
安全保护响应 ≤ 50 ms。从越界事件被检测到切断增强输出的时间，须显著短于人体受到伤害的最短时间尺度。
PR-4
执行机构定位与出力误差在指标内。关节角度与输出力矩的稳态误差，按设计指标逐项验收。
PR-5
连续工作 8 小时无单点失效。考核项包含电量、温升、信号漂移与机械磨损，任一项超标即视为不通过。
PR-6
采集信噪比满足算法最低要求。以意图识别算法能稳定工作的最小信噪比为验收下限。

5.3接口需求 IR

接口是"系统与外部世界握手的地方"，也是故障与安全风险最集中的地方。

IR-1
生物采集接口。干／湿电极接入，脑电与肌电共用采集前端，接触面须为医用级设计。
IR-2
机器执行接口。外骨骼动力单元、声光增强提示模块采用统一的通信协议与供电规范。
IR-3
人机交互接口。提供触控终端，并保留独立的物理急停按钮——后者不依赖软件栈。
IR-4
数据接口。日志以通用格式导出，可在医师端软件中直接读取分析，不依赖专用上位机。
IR-5
供电接口。可充电电池供电，电源与人体之间须做电气隔离，防漏电与反向电流。

5.4安全需求 SR

安全需求的写法特点：失效即默认安全，也就是"坏了就停"，而不是"坏了还在跑"。

SR-1
随时可切断。使用者可通过原生神经动作或物理急停，在任意时刻切断增强输出，此路径优先级高于一切。
SR-2
双重故障安全。软硬件各设一层保护，任一模块失效时系统默认回到无增强状态。
SR-3
电气隔离。防止漏电与电刺激损伤神经组织，接触部位须限制输出电流上限。
SR-4
分级告警。信号异常或生命体征超标时，按"提示 → 限制增强 → 强制停机"三级递进响应。
SR-5
数据安全。存储的神经信号与健康数据须加密，访问须授权并留痕，满足隐私保护要求。

5.5设计约束 DR

这些不是"需求"，而是"先天地限定了方案空间"的条件，通常来自标准、法规或既有架构。

DR-1
所有接触人体的材料须满足医用生物相容性要求。
DR-2
设备须电磁兼容，不干扰心脏起搏器等其他植入式医疗设备。
DR-3
整机须控制重量与体积，降低长期佩戴的负荷与体感负担。
DR-4
系统架构须与六层分解一致：任务 → 体系 → 整机 → 系统 → 子系统 → 模块。
DR-5
算法与硬件模块须可独立测试验证，避免出现只能整机联调的黑盒。
